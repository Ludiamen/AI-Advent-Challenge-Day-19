# Ручная проверка Дня 19 в браузере

Сценарий для проверки руками: агент умеет выполнять **цепочки инструментов**.
Первый шаг получает данные, второй обрабатывает, третий сохраняет результат
файлом; цепочка описана заранее в `pipelines.json`, а данные между шагами едут
по ссылкам `${шаг.данные.поле}`, и это видно в протоколе прогона.

Каждый шаг устроен одинаково: **что сделать** → **что должно получиться**.

Время: около 30 минут. Вызовов модели: 3–5. В шапке выберите модель
**DeepSeek V4 Flash (ds-flash)**: она отвечает быстро и уверенно пользуется
инструментами.

Сценарий пройден в браузере (headless Chrome, порт 5001) на живом моке трекера
и живой модели: ожидания ниже — то, что происходит на самом деле.

Этот файл — для человека. Если нужно **показать** день, а не проверить, есть
отдельный сценарий: [DEMO-CHROME.md](DEMO-CHROME.md) — шесть сцен с готовым
промптом для браузерного расширения Claude in Chrome, стенд одной командой
(`bash demo_stand.sh`) и запись окна браузера (`bash record_demo.sh`). Тот же
сценарий проходит и скрипт-водитель, если расширение не подключилось:
`bash demo_show.sh`.

## Часть 0. Подготовка

Понадобятся **два терминала** (третий — для части 8, там нужен работник).

```bash

cd ~/Документы/AI-Advent-Challenge/Day-19
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt     # Flask, httpx и MCP SDK (mcp 2.x)
cp -n .env.example .env                       # если .env ещё нет
mv memory memory-до-проверки 2>/dev/null || true
rm -rf reports                                # чтобы было видно, что файлы новые
.venv/bin/python web.py
```

```bash
# терминал 2 — API, вокруг которого построен инструмент Дня 17
cd ~/Документы/AI-Advent-Challenge/Day-19
.venv/bin/python tracker_api.py --сброс       # 127.0.0.1:8766, данные заново
```

Откройте `http://127.0.0.1:5001`.

- [ ] Заголовок страницы: «Агент миграции ГИС — композиция MCP-инструментов».
- [ ] Во вступлении сказано про конвейер и `${шаг.данные.поле}`.

Системный `python3` не подойдёт: в нём нет ни Flask, ни MCP SDK.

## Часть 6. Модель сама выбирает цепочку

**6.1.** Включите переключатель **Давать инструменты модели**, в поле рядом

- [ ] Отдельная строка «↳ конвейер «отчёт» — готов, 4/4 шагов: reports/…».

- [ ] Комментарий в трекере не появился (проверить можно вызовом

## Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| панель «Конвейеры» пустая, красная строка «Описание испорчено» | в `pipelines.json` ошибка — текст ошибки называет шаг и ссылку; `git checkout pipelines.json` вернёт исходный файл |
| шаг `tracker__list_issues` упал: «Трекер не отвечает» | не поднят мок: `.venv/bin/python tracker_api.py` во втором терминале |
| у шага «выжимка» текст вида «Выжимка: … Цифры: …» | модель не вызывалась: нет ключа или `PIPELINE_MODEL=нет`. Цифры важнее текста, поэтому шаг не падает |
| прогон «сбой» на первом же шаге с «Сервер … не выполнил вызов» | сервер шага не запускается: проверьте `cli.py --mcp pipeline` |
| ошибка «Ссылка «…» ведёт в никуда» при запуске | цепочка ссылается на поле, которого инструмент не вернул. Путь назван целиком — поправьте `pipelines.json` |
| файл отчёта не появился | смотрите, дошла ли цепочка до последнего шага: при сбое она останавливается намеренно |
| модель зовёт инструменты по одному вместо `run_pipeline` | в поле серверов не указан `pipeline`, либо модель не спросила `list_pipelines`. Попросите её прямо: «посмотри список конвейеров» |
| «Вызов не выполнен: … выполнит конвейер …» | так и задумано: в цепочке есть шаг в чужую систему, подтвердите заявку |
| `ModuleNotFoundError: No module named 'flask'` или `'mcp'` | запущен системный `python3` — запускайте `.venv/bin/python` |
